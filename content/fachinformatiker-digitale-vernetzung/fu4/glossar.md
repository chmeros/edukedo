## Glossar

#### Programmierparadigma
**Auch:** Paradigma, Paradigmen, Programmierparadigmen
**Thema:** 4.1
**Abschnitt:** Was ist ein Programmierparadigma?
**Definition:** Ein grundlegender Denk- und Strukturierungsstil, nach dem ein Programm aufgebaut wird. Beispiele sind das prozedurale, das objektorientierte, das funktionale und das deklarative Paradigma.
**Geprüft:** nein

#### Kapselung
**Auch:** Datenkapselung
**Thema:** 4.1
**Abschnitt:** Objektorientierte Programmierung (OOP)
**Definition:** Interne Daten eines Objekts werden verborgen und nur über definierte Methoden zugänglich gemacht. Jede Änderung durchläuft so die Prüfregeln der Klasse, ungültige Werte werden verhindert.
**Geprüft:** nein

#### Vererbung
**Thema:** 4.1
**Abschnitt:** Objektorientierte Programmierung (OOP)
**Definition:** Eine Klasse übernimmt Attribute und Methoden einer Oberklasse und kann sie erweitern oder anpassen. Das vermeidet doppelten Code.
**Geprüft:** nein

#### Polymorphie
**Auch:** Vielgestaltigkeit
**Thema:** 4.1
**Abschnitt:** Objektorientierte Programmierung (OOP)
**Definition:** Dieselbe Methode kann bei verschiedenen Objekttypen unterschiedlich ausgeführt werden. Der aufrufende Code muss den genauen Typ nicht kennen.
**Geprüft:** nein

#### Compiler
**Thema:** 4.1
**Abschnitt:** Programmiersprachen unterscheiden
**Definition:** Ein Programm, das den gesamten Quelltext vor der Ausführung in Maschinencode übersetzt. Das Ergebnis ist meist schnell, aber plattformabhängig. Ein Interpreter führt den Quelltext dagegen zur Laufzeit schrittweise aus.
**Geprüft:** nein

#### Algorithmus
**Auch:** Algorithmen
**Thema:** 4.2
**Abschnitt:** Was ist ein Algorithmus?
**Definition:** Eine eindeutige, endliche Folge von Anweisungen, die ein Problem löst oder eine Aufgabe erledigt. Er ist ausführbar, allgemeingültig und liefert bei gleichen Eingaben gleiche Ergebnisse.
**Geprüft:** nein

#### Stack
**Auch:** Stapel, LIFO
**Thema:** 4.2
**Abschnitt:** Einfache Datenstrukturen
**Definition:** Eine Datenstruktur nach dem Prinzip LIFO (Last In, First Out): Das zuletzt abgelegte Element wird zuerst entnommen. Die Operationen heißen üblicherweise push und pop.
**Geprüft:** nein

#### Queue
**Auch:** Warteschlange, FIFO
**Thema:** 4.2
**Abschnitt:** Einfache Datenstrukturen
**Definition:** Eine Datenstruktur nach dem Prinzip FIFO (First In, First Out): Das älteste Element kommt zuerst dran. Typisch sind Druckaufträge oder Support-Tickets.
**Geprüft:** nein

#### Dictionary
**Auch:** Assoziatives Array, Map
**Thema:** 4.2
**Abschnitt:** Einfache Datenstrukturen
**Definition:** Eine Sammlung von Schlüssel-Wert-Paaren. Der Zugriff erfolgt über den Schlüssel statt über eine Position, zum Beispiel über eine Sensor-ID.
**Geprüft:** nein

#### Programmablaufplan
**Auch:** PAP, Programmablaufpläne
**Thema:** 4.2
**Abschnitt:** Algorithmen darstellen
**Definition:** Eine grafische Darstellung eines Algorithmus mit genormten Symbolen (DIN 66001): Oval für Start und Ende, Rechteck für Verarbeitung, Raute für Verzweigung, Parallelogramm für Ein- und Ausgabe, Pfeile für den Ablauf.
**Geprüft:** nein

#### Struktogramm
**Auch:** Nassi-Shneiderman-Diagramm
**Thema:** 4.2
**Abschnitt:** Algorithmen darstellen
**Definition:** Eine Darstellung aus ineinander verschachtelten Rechtecken ohne Pfeile. Sie erzwingt einen strukturierten Aufbau, weil sie keine beliebigen Sprünge kennt.
**Geprüft:** nein

#### Binäre Suche
**Auch:** Binärsuche
**Thema:** 4.2
**Abschnitt:** Einfache Such- und Sortierverfahren
**Definition:** Ein Suchverfahren für sortierte Listen. In jedem Schritt wird das mittlere Element verglichen und eine Hälfte des Suchbereichs verworfen, sodass nur wenige Vergleiche nötig sind.
**Geprüft:** nein

#### Syntaxfehler
**Thema:** 4.3
**Abschnitt:** Fehlerarten unterscheiden
**Definition:** Der Code verstößt gegen die Grammatik der Sprache, zum Beispiel durch einen fehlenden Doppelpunkt. Compiler oder Interpreter melden ihn, bevor das Programm läuft.
**Geprüft:** nein

#### Laufzeitfehler
**Thema:** 4.3
**Abschnitt:** Fehlerarten unterscheiden
**Definition:** Der Code ist syntaktisch korrekt, aber während der Ausführung tritt ein Problem auf, das zu einer Ausnahme führt, zum Beispiel eine Division durch null.
**Geprüft:** nein

#### Logikfehler
**Thema:** 4.3
**Abschnitt:** Fehlerarten unterscheiden
**Definition:** Das Programm läuft ohne Fehlermeldung, liefert aber ein falsches Ergebnis, weil die Idee oder die Bedingung falsch umgesetzt wurde. Niemand wird automatisch gewarnt.
**Geprüft:** nein

#### Regressionstest
**Auch:** Regressionstests
**Thema:** 4.3
**Abschnitt:** Systematisch vorgehen
**Definition:** Eine erneute Prüfung nach einer Fehlerbehebung. Sie stellt sicher, dass der Fehler weg ist und nichts anderes kaputtgegangen ist.
**Geprüft:** nein

#### Haltepunkt
**Auch:** Breakpoint, Haltepunkte
**Thema:** 4.3
**Abschnitt:** Debugging und Logging
**Definition:** Eine markierte Zeile, an der der Debugger das Programm anhält. So lassen sich Variablenwerte und Ablauf an dieser Stelle untersuchen.
**Geprüft:** nein

#### Exit-Code
**Thema:** 4.3
**Abschnitt:** Teilaufgaben automatisieren
**Definition:** Der definierte Rückgabewert eines Skripts, mit dem aufrufende Systeme den Erfolg auswerten können. Üblich ist 0 für Erfolg und ein Wert ungleich 0 für einen Fehler.
**Geprüft:** nein

#### cron
**Auch:** Crontab, Cronjob
**Thema:** 4.3
**Abschnitt:** Zeitplanung und Betrieb automatisierter Aufgaben
**Definition:** Der unter Linux übliche Zeitplaner, der Skripte automatisch startet. Die Konfiguration steht in einer Crontab, deren Zeilen aus fünf Zeitfeldern und dem Befehl bestehen.
**Geprüft:** nein

#### Nicht-funktionale Anforderung
**Auch:** nicht-funktionale Anforderungen
**Thema:** 4.4
**Abschnitt:** Anforderungen unterscheiden
**Definition:** Eine Anforderung, die Qualitätseigenschaften und Randbedingungen beschreibt, etwa Leistung, Zuverlässigkeit, Sicherheit, Bedienbarkeit oder Wartbarkeit. Funktionale Anforderungen beschreiben dagegen, was das System tun soll.
**Geprüft:** nein

#### API
**Auch:** Application Programming Interface, Programmierschnittstelle
**Thema:** 4.4
**Abschnitt:** Schnittstellen — Begriff und Arten
**Definition:** Eine Programmierschnittstelle zwischen Programmen oder Programmteilen. Der Anbieter veröffentlicht einen verlässlichen Vertrag über Funktionen, Daten und Fehler; die interne Umsetzung muss der Nutzer nicht kennen.
**Geprüft:** nein

#### JSON
**Auch:** JavaScript Object Notation
**Thema:** 4.4
**Abschnitt:** Datenformate: JSON, XML und CSV
**Definition:** Ein kompaktes Textformat aus Objekten in geschweiften Klammern, Arrays in eckigen Klammern und einfachen Werten wie Zeichenketten, Zahlen, true/false und null. Es sieht keine Kommentare vor.
**Geprüft:** nein

#### XML
**Auch:** Extensible Markup Language
**Thema:** 4.4
**Abschnitt:** Datenformate: JSON, XML und CSV
**Definition:** Ein Format, das Daten mit verschachtelten Tags und optionalen Attributen beschreibt. Ein Dokument ist wohlgeformt, wenn es genau ein Wurzelelement hat und alle Elemente korrekt geöffnet, geschlossen und verschachtelt sind.
**Geprüft:** nein
