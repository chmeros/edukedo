# Thema 4.1 — Programmierparadigmen und Programmiersprachen

## Theorie

### Warum Programmieren in allen Fachrichtungen vorkommt

Die Fachinformatikerausbildung gliedert sich nach § 4 Abs. 1 FIAusbV in fachrichtungsübergreifende Inhalte und fachrichtungsspezifische Inhalte. Programmieren gehört zu den fachrichtungsübergreifenden Berufsbildpositionen: „Entwickeln, Erstellen und Betreuen von IT-Lösungen" (§ 4 Abs. 2 Nr. 4) und „Programmieren von Softwarelösungen" (§ 4 Abs. 2 Nr. 10) betreffen also alle vier Fachrichtungen. Im Ausbildungsrahmenplan ist dazu unter anderem verlangt, Programmiersprachen — insbesondere prozedurale und objektorientierte — zu unterscheiden und für eine Aufgabe auszuwählen.

Bei der Brevanta IT-Systemhaus GmbH zeigt sich das im Alltag aller vier Bereiche: Das Team Softwareentwicklung baut ein Kundenportal für einen Maschinenbauer, die Systemintegration schreibt Skripte zur Verwaltung hunderter Clients, die Datenanalyse wertet Verkaufszahlen eines Händlers aus, und im Smart-Factory-Bereich wird Steuerlogik für Sensoren in einer Abfüllanlage programmiert. Alle brauchen dieselben Grundkonzepte, nutzen aber unterschiedliche Sprachen.

### Was ist ein Programmierparadigma?

Ein **Programmierparadigma** ist ein grundlegender Denk- und Strukturierungsstil, nach dem ein Programm aufgebaut wird. Es beantwortet die Frage: Wie zerlege ich ein Problem in Bausteine, und wie gehören Daten und Verarbeitung zusammen? Die wichtigsten Paradigmen für den Einstieg sind das **prozedurale** und das **objektorientierte** Paradigma. Daneben gibt es unter anderem das **funktionale** Paradigma (Programme als Verkettung von Funktionen ohne veränderliche Zustände) und das **deklarative** Paradigma (man beschreibt, *was* gewünscht ist, nicht *wie* es berechnet wird — typisch bei Datenbankabfragen). Viele moderne Sprachen sind Mehrparadigmen-Sprachen und erlauben, mehrere Stile zu mischen.

### Prozedurale Programmierung

Beim prozeduralen Ansatz besteht ein Programm aus einer Folge von Anweisungen, die in **Prozeduren** bzw. **Funktionen** gebündelt werden. Daten und die Funktionen, die sie verarbeiten, sind getrennt: Die Funktion bekommt Daten als Parameter und liefert ein Ergebnis oder verändert Daten.

```python
def netto_zu_brutto(netto, steuersatz):
    return netto * (1 + steuersatz)

preis = netto_zu_brutto(100.0, 0.19)
print(preis)   # Ausgabe: 119.0
```

Vorteile: leicht verständlich, direkt, gut für kleinere Programme und Skripte. Nachteil: Bei wachsender Programmgröße wird es unübersichtlich, wenn viele Funktionen auf denselben Daten arbeiten und jeder alles verändern darf. Klassische Vertreter prozeduraler Sprachen sind C oder Pascal; auch Python und viele Shell-Skripte werden häufig prozedural genutzt.

### Objektorientierte Programmierung (OOP)

Die objektorientierte Programmierung bündelt **Daten und die zugehörigen Funktionen** in Einheiten, den Objekten. Die zentralen Begriffe:

- **Klasse:** der Bauplan. Sie legt fest, welche **Attribute** (Eigenschaften, Daten) und **Methoden** (Funktionen, Verhalten) Objekte dieses Typs haben.
- **Objekt (Instanz):** ein konkretes Exemplar einer Klasse mit eigenen Attributwerten, z. B. der Sensor „Temperatur-1".
- **Kapselung:** Interne Daten werden verborgen und nur über definierte Methoden zugänglich gemacht. So lassen sich Fehler wie ungültige Werte verhindern, weil jede Änderung die Prüfregeln der Klasse durchläuft.
- **Vererbung:** Eine Klasse übernimmt Attribute und Methoden einer Oberklasse und kann sie erweitern oder anpassen. Das vermeidet doppelten Code.
- **Polymorphie:** Dieselbe Methode kann bei verschiedenen Objekttypen unterschiedlich ausgeführt werden. Der aufrufende Code muss den genauen Typ nicht kennen.

```python
class Geraet:
    def __init__(self, name):
        self.name = name
        self._betriebsstunden = 0      # Unterstrich: "intern, nicht von außen ändern"

    def laufzeit_erfassen(self, stunden):
        if stunden > 0:                # Kapselung: Prüfregel schützt den Zustand
            self._betriebsstunden += stunden

    def beschreibung(self):
        return f"Gerät {self.name}"

class Sensor(Geraet):                  # Vererbung: Sensor erbt von Geraet
    def beschreibung(self):            # Polymorphie: überschriebene Methode
        return f"Sensor {self.name}"

for g in [Geraet("Router"), Sensor("Temperatur-1")]:
    print(g.beschreibung())
# Ausgabe:
# Gerät Router
# Sensor Temperatur-1
```

Die Schleife ruft für beide Objekte `beschreibung()` auf; je nach tatsächlichem Typ läuft die passende Variante. Hinweis zur Sprache: Python kennt Kapselung nur als Konvention (Unterstrich), Sprachen wie Java oder C# erzwingen sie mit Schlüsselwörtern wie `private`.

Objektorientierung lohnt sich vor allem bei größeren Anwendungen, die fachliche Dinge abbilden (Kunde, Auftrag, Maschine) und von mehreren Personen gepflegt werden. Für ein kurzes Auswertungsskript wäre sie oft unnötiger Aufwand.

### Programmiersprachen unterscheiden

Programmiersprachen lassen sich nach mehreren, voneinander unabhängigen Merkmalen einordnen:

- **Ausführungsmodell:**
  - *Kompiliert:* Ein Compiler übersetzt den gesamten Quelltext vor der Ausführung in Maschinencode (z. B. C, C++, Rust). Ergebnis ist meist schnell, aber das Programm ist plattformabhängig.
  - *Interpretiert:* Ein Interpreter führt den Quelltext zur Laufzeit schrittweise aus (z. B. klassische Shell-Skripte, JavaScript im Browser, Python). Änderungen sind schnell testbar, die Ausführung ist oft langsamer.
  - *Zwischenform:* Java und C# werden in Bytecode übersetzt, den eine virtuelle Maschine ausführt; Python erzeugt intern ebenfalls Bytecode. Die Grenze zwischen „kompiliert" und „interpretiert" ist daher fließend und hängt von der Implementierung ab.
- **Typisierung:**
  - *Statisch typisiert:* Datentypen werden vor der Ausführung festgelegt und geprüft (z. B. Java, C#). Typfehler fallen früh auf.
  - *Dynamisch typisiert:* Typen gehören zu den Werten und werden zur Laufzeit geprüft (z. B. Python, JavaScript). Das ist flexibel, Typfehler zeigen sich aber erst bei der Ausführung.
- **Paradigma:** prozedural, objektorientiert, funktional, deklarativ oder gemischt.
- **Einsatzgebiet:** Systemnahe Sprachen (C, Rust), Anwendungssprachen (Java, C#), Skriptsprachen (Python, Bash, PowerShell), Abfragesprachen (SQL).

### Programmiersprachen auswählen

Die Wahl der Sprache ist eine fachliche Entscheidung und sollte anhand nachvollziehbarer Kriterien getroffen werden:

- **Aufgabe und Einsatzumgebung:** Webanwendung, Desktop-Programm, Skript für Serveradministration, Auswertung großer Datenmengen, Steuerung eingebetteter Geräte?
- **Zielplattform:** Läuft das Programm auf Windows, Linux, im Browser oder auf einem Mikrocontroller mit wenig Speicher?
- **Verfügbare Bibliotheken und Frameworks:** Gibt es fertige Bausteine für das Problem (z. B. Datenanalyse, Webschnittstellen)?
- **Know-how im Team und Einarbeitungsaufwand:** Eine Sprache, die niemand im Team kennt, verursacht Kosten und Risiken.
- **Leistungsanforderungen:** Zeitkritische Steuerungen verlangen andere Sprachen als ein nächtlicher Berichtslauf.
- **Wartbarkeit und Lebensdauer:** Wird die Sprache langfristig gepflegt, gibt es Community und Dokumentation?
- **Lizenz und Kosten:** Sind Werkzeuge und Laufzeitumgebungen für den geplanten Einsatz lizenzrechtlich nutzbar?
- **Anbindung an bestehende Systeme:** Kundenvorgaben oder vorhandene Schnittstellen können die Wahl einschränken.

Beispiel: Für ein wöchentliches Auswertungsskript im Bereich Datenanalyse wählt Brevanta eine Skriptsprache mit guten Datenbibliotheken; für die Steuerlogik eines Sensorknotens mit 64 KB Speicher kommt eher eine kompilierte, systemnahe Sprache infrage; für ein langlebiges Kundenportal mit großem Team eine statisch typisierte Anwendungssprache mit starkem Ökosystem. Eine einzige „beste" Sprache gibt es nicht — entscheidend ist die Passung zur Aufgabe.
