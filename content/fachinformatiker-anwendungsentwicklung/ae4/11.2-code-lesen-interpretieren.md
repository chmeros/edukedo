# Thema 11.2 — Programmcode interpretieren, Fehler finden und Lösungen erstellen

## Theorie

### Code lesen heißt: den Computer im Kopf spielen

In der schriftlichen Prüfung (§ 14 Abs. 1 Nr. 1 FIAusbV) wird häufig ein kurzer Code-Ausschnitt vorgelegt. Gefragt ist, was er bei bestimmten Eingaben ausgibt, welchen Zweck er hat, wo ein Fehler steckt oder wie er zu ergänzen ist. Die verlässlichste Methode ist die **Ablaufverfolgung (Trace)**: Man führt den Code Zeile für Zeile von Hand aus und hält die Werte aller beteiligten Variablen in einer **Trace-Tabelle** fest. Wer rät oder „nach Gefühl" liest, übersieht typischerweise Grenzfälle wie den ersten oder letzten Schleifendurchlauf.

Die Beispiele hier sind in Python geschrieben, weil die Sprache nah am Pseudocode liegt. Wichtige Grundlagen, die in solchen Aufgaben vorausgesetzt werden:

- `=` weist zu, `==` vergleicht. `+=` addiert und weist zu (`s += 2` entspricht `s = s + 2`).
- `/` liefert immer eine Kommazahl (`7 / 2` ergibt `3.5`), `//` die ganzzahlige Division (`7 // 2` ergibt `3`), `%` den Rest der Ganzzahldivision (`7 % 2` ergibt `1`).
- `range(a, b)` erzeugt die Zahlen von `a` bis `b - 1`; die Obergrenze gehört nicht dazu. `range(4)` liefert 0, 1, 2, 3.
- Listen und Zeichenketten werden ab Index 0 gezählt; `liste[-1]` ist das letzte Element, `"Brevanta"[0:3]` ergibt `"Bre"`, `len(liste)` die Anzahl der Elemente.
- Die Einrückung bestimmt in Python, was zu einem Block (Schleifenkörper, Zweig) gehört.

### Verzweigungen nachvollziehen

```python
def bonus(umsatz):
    if umsatz >= 10000:
        satz = 5
    elif umsatz >= 5000:
        satz = 3
    else:
        satz = 0
    return umsatz * satz // 100
```

Die Funktion berechnet einen Vertriebsbonus in Prozent des Umsatzes. Bei `bonus(12000)` ist die erste Bedingung erfüllt, `satz` ist 5, das Ergebnis `12000 * 5 // 100` ist 600. Bei `bonus(5000)` greift der `elif`-Zweig (die Grenze 5000 gehört dazu, denn `>=`), das Ergebnis ist 150. Bei `bonus(4999)` greift `else`, das Ergebnis ist 0. Beachten Sie: Von mehreren `if`/`elif`-Zweigen wird höchstens einer ausgeführt, und die Reihenfolge der Bedingungen ist entscheidend.

### Schleifen nachvollziehen: die Trace-Tabelle

```python
summe = 0
i = 1
while i <= 10:
    if i % 3 == 0:
        summe += i
    i += 1
```

Die Schleife addiert alle durch 3 teilbaren Zahlen von 1 bis 10. Trace-Tabelle (Werte jeweils zu Beginn des Durchlaufs, `summe` nach dem Durchlauf):

```
Durchlauf |  i | i % 3 == 0 | summe danach
----------+----+------------+-------------
    1     |  1 |    nein    |     0
    2     |  2 |    nein    |     0
    3     |  3 |    ja      |     3
    4     |  4 |    nein    |     3
    5     |  5 |    nein    |     3
    6     |  6 |    ja      |     9
    7     |  7 |    nein    |     9
    8     |  8 |    nein    |     9
    9     |  9 |    ja      |    18
   10     | 10 |    nein    |    18
```

Danach ist `i` gleich 11, die Bedingung `i <= 10` ist falsch, die Schleife endet; `summe` ist 18 (3 + 6 + 9). Diese Tabellenform zeigt auch sofort, wie oft die Schleife läuft.

### Funktionen und Rekursion

Eine **Funktion** kapselt einen Teilalgorithmus: Sie nimmt Parameter entgegen und liefert mit `return` einen Rückgabewert. Eine **rekursive** Funktion ruft sich selbst mit einem kleineren Problem auf. Sie braucht zwingend eine **Abbruchbedingung** (Basisfall), die ohne weiteren Selbstaufruf ein Ergebnis liefert, sonst entsteht eine endlose Rekursion (in Python ein `RecursionError`).

```python
def fak(n):
    if n <= 1:
        return 1
    return n * fak(n - 1)
```

Für `fak(3)` entstehen die Aufrufe `fak(3)`, `fak(2)`, `fak(1)`. `fak(1)` liefert 1 zurück (Abbruch), danach wird von innen nach außen aufgelöst: `fak(2)` ist `2 * 1 = 2`, `fak(3)` ist `3 * 2 = 6`. Weitere Werte: `fak(4)` ist 24, `fak(5)` ist 120. Eine Rekursion lässt sich meist auch als Schleife formulieren; die Schleife ist oft speicherschonender, die Rekursion manchmal kürzer und näher an der mathematischen Definition.

### Fehlerarten und typische Fehlerbilder

- **Syntaxfehler:** Der Code verletzt die Regeln der Sprache (z. B. fehlender Doppelpunkt, `if x = 5:`). Er wird gemeldet, bevor das Programm läuft.
- **Laufzeitfehler:** Das Programm startet, bricht aber bei bestimmten Daten ab, z. B. `ZeroDivisionError` (Division durch 0), `IndexError` (Listenindex existiert nicht), `NameError` (Variable nicht definiert), `TypeError` (falscher Datentyp), `RecursionError` (zu tiefe Rekursion).
- **Logikfehler:** Das Programm läuft ohne Meldung, liefert aber ein falsches Ergebnis. Diese Fehler sind am schwersten zu finden, weil das System keine Fehlermeldung erzeugt.

Häufige Logikfehler: **Off-by-one** (Schleife beginnt oder endet einen Schritt zu früh/spät), vertauschte oder falsche Vergleichsoperatoren (`<` statt `<=`), nicht initialisierte oder falsch zurückgesetzte Variablen, eine Schleifenvariable, die nie verändert wird (Endlosschleife), sowie nicht behandelte Sonderfälle wie die leere Liste.

Beispiel 1 — Off-by-one beim Zählen offener Tickets:

```python
def zaehle_offene(tickets):
    anzahl = 0
    for i in range(1, len(tickets)):
        if tickets[i] == "offen":
            anzahl += 1
    return anzahl
```

Für `["offen", "offen", "erledigt"]` liefert die Funktion 1 statt der erwarteten 2, denn `range(1, len(tickets))` überspringt Index 0. Korrektur: `range(len(tickets))` oder gleich `for t in tickets:`.

Beispiel 2 — nicht behandelter Sonderfall:

```python
def durchschnitt(werte):
    summe = 0
    for w in werte:
        summe += w
    return summe / len(werte)
```

Für `[4, 8, 12]` ist das Ergebnis 8.0. Für eine leere Liste ist `len(werte)` gleich 0 und es kommt zu einem `ZeroDivisionError`. Korrektur: vorab `if len(werte) == 0: return None` (oder bewusst einen Fehler melden, je nach Fachanforderung).

Systematisches Vorgehen bei der Fehlersuche (vgl. Ausbildungsrahmenplan Abschnitt A, lfd. Nr. 4 Buchst. c „systematisch Fehler erkennen, analysieren und beheben"): (1) Fehler reproduzieren, (2) eingrenzen — z. B. mit Kontrollausgaben oder Haltepunkten im Debugger, (3) Ursache verstehen und beheben, (4) erneut testen, auch die bereits funktionierenden Fälle.

### Komplexität — nur qualitativ

Im Prüfungsbereich genügt in der Regel eine qualitative Einschätzung, wie sich der Aufwand mit der Datenmenge `n` ändert:

- Eine einzelne Schleife über alle `n` Elemente: Der Aufwand wächst **proportional** zu `n` (linear). Verdoppelt sich die Datenmenge, verdoppelt sich ungefähr die Laufzeit.
- Zwei ineinander verschachtelte Schleifen über je `n` Elemente (z. B. jeder Eintrag wird mit jedem anderen verglichen): Der Aufwand wächst **quadratisch**; bei doppelter Datenmenge etwa das Vierfache.
- Ein Verfahren, das die Datenmenge in jedem Schritt halbiert (z. B. binäre Suche in einer sortierten Liste): Der Aufwand wächst nur sehr langsam (logarithmisch).

### Lösungen in einer Programmiersprache erstellen

Typische Aufgabe: „Ergänzen Sie die Funktion …" oder „Schreiben Sie eine Funktion, die …". Vorgehen: Eingaben, Ausgabe und Sonderfälle klären, dann in kleinen Schritten formulieren. Beispiel: Die höchste Rechnungssumme aus einer Liste ermitteln.

```python
def hoechster_betrag(betraege):
    if not betraege:
        return None
    hoechster = betraege[0]
    for b in betraege:
        if b > hoechster:
            hoechster = b
    return hoechster
```

`hoechster_betrag([120.5, 99.0, 310.0])` liefert `310.0`, bei einer leeren Liste `None`. Ein weiteres Muster ist das Filtern in eine neue Liste:

```python
def ueber_schwelle(betraege, schwelle):
    ergebnis = []
    for b in betraege:
        if b > schwelle:
            ergebnis.append(b)
    return ergebnis
```

`ueber_schwelle([120, 80, 250, 100], 100)` liefert `[120, 250]` — der Wert 100 ist nicht größer als 100 und fehlt deshalb. Typische Grundmuster, die in Prüfungsaufgaben immer wiederkehren: Zählen, Summieren, Maximum/Minimum bestimmen, Filtern, Suchen, Umwandeln. Nutzen Sie die Python-Standardfunktionen (`len`, `sum`, `max`, `min`, `sorted`), wenn die Aufgabe das nicht ausdrücklich verbietet; wird verlangt, den Algorithmus selbst zu formulieren, bilden Sie ihn mit Schleife und Verzweigung nach. Wenn keine bestimmte Sprache vorgegeben ist, ist auch klar gekennzeichneter Pseudocode zulässig — achten Sie dann besonders auf Eindeutigkeit.
